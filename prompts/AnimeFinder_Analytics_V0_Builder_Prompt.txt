ANIMEFINDER — ANALYTICS V0
YOUR ANALYTICS + FOR NERDS SUMMARY + DEEP ANALYSIS PAGE

Upgrade the existing AnimeFinder Anime Details architecture.

DO NOT rebuild the application.

Preserve:
- Authentication
- Supabase
- Discover
- Personal Catalog
- Watched state
- Anime Details
- Related Works
- Franchise Average
- Synopsis
- Dark / Light themes
- Existing provider architecture
- GitHub Pages compatibility

OBJECTIVE
Introduce a lightweight analytics layer into each Anime Details page while creating a separate view for advanced/heavy analytics. Anime Details must remain fast. Heavy analytics, geographic datasets, large franchise graphs and future multi-source market datasets must load only after the user explicitly opens Deep Analysis.

==================================================
1. ANIME DETAILS STRUCTURE
==================================================
The Anime Details page should follow:
1. Anime Overview
2. Synopsis
3. Related Works
4. Your Analytics
5. For Nerds — Advanced Database
6. Deep Analysis button

Do not remove or break existing Details V2 functionality.

==================================================
2. YOUR ANALYTICS
==================================================
Create a section before For Nerds called “Your Analytics”.
It uses Leonardo's private AnimeFinder catalog data and must remain visually distinct from public MAL statistics.

Prioritize reliable currently available metrics:
- Watched status
- My Ranked position
- Personal ranking percentile
- Original observations
- Personal comments
- Franchise completion
- Related/franchise works already watched

When sufficient cached metadata exists, architecture may later support:
- Studio affinity
- Director affinity
- Creator / Mangaka affinity
- Similar watched works

Do not scan the entire watched catalog with dozens/hundreds of API calls during normal Anime Details load. Only show affinity metrics when enough cached data exists.

If a watched anime has My Ranked, show conceptually:
✓ Watched
My Ranking: #3 of N
Top: 2.1%
Original Observation: ...
Comments: ...

N must be calculated dynamically from the Personal Catalog. Never hardcode the catalog size.

==================================================
3. FOR NERDS — ADVANCED DATABASE
==================================================
Keep “For Nerds” and the subtitle/concept “Advanced Database”.
This must be compact: roughly “20 technical facts / indicators at a glance”, not a huge research page.

Support these 20 indicator categories with explicit states:
1. Director
2. Original Creator / Mangaka
3. Main Voice Cast
4. Animation Studio
5. Production Staff
6. Original Source
7. Publisher / Magazine
8. Manga Volumes / Chapters
9. Manga Sales
10. Total Circulation
11. Sales Evolution
12. Anime Effect on Source Sales
13. MAL Statistics
14. Franchise Score Timeline
15. International Distribution
16. Brazil Availability / Distribution
17. Streaming Availability
18. Movie Box Office
19. Awards & Nominations
20. Franchise Analytics

Every indicator supports:
- available
- partial
- unavailable
- loading
- error
- timeout

Never fabricate missing information. Use “No reliable data” when unsupported.
One failed provider/source must not block the whole dashboard.

Group indicators compactly, for example:
PRODUCTION: Director, Creator, Studio, Source, Publisher, Staff, Cast
MANGA: Volumes, Circulation, Sales, Sales Evolution, Anime Effect
AUDIENCE / MARKET: MAL Rank, Popularity, Members, Favorites, Distribution, Streaming, Box Office
FRANCHISE: Franchise Average, Score Range, Highest/Lowest, Timeline

==================================================
4. MINI FRANCHISE SCORE TIMELINE
==================================================
Inside For Nerds add a small lightweight Franchise Score Timeline.
Use Related Works data already loaded by AnimeFinder.
Do not make new provider requests when existing franchise data already contains title/year/MAL score.
X-axis: chronological franchise entries.
Y-axis: MAL score.
Missing scores are ignored, not treated as zero.

==================================================
5. DEEP ANALYSIS
==================================================
At the bottom of For Nerds add a prominent “Deep Analysis” action with subtitle:
“Advanced charts, markets, franchise and global analytics”.

This opens a dedicated analytics view for the selected MAL ID.
The implementation must remain GitHub Pages compatible.
The heavy analytics view must not load until the user explicitly opens it.

Header:
[poster]
Anime Title
Deep Analysis
Advanced franchise, audience and market analytics
Provide a clear return action to Anime Details.

==================================================
6. DEEP ANALYSIS SECTIONS
==================================================
Create six major sections:
1. Franchise Analytics
2. Production & People
3. Source & Manga
4. Audience Analytics
5. Business & Markets
6. Global Footprint

Partial/no-data states are acceptable and preferred over invented data.

==================================================
7. FRANCHISE ANALYTICS
==================================================
Use the existing Related Works / Franchise graph whenever possible.
Calculate only from valid MAL scores:
- Franchise Average
- Highest Rated Entry
- Lowest Rated Entry
- Score Range
- Standard Deviation
- Number of Related Works
- Chronological Score Timeline

Do not count missing scores as zero.

Add a larger responsive interactive Score Timeline.

==================================================
8. FRANCHISE MAP
==================================================
Create a simple responsive relationship visualization based on MAL IDs and known structured relations.
Conceptually:
Original Source → Anime S1 → Anime S2 → Movie / OVA / Spin-off

Reuse the existing franchise relationship data and caches.
Nodes should be architected for navigation/clicking.
Do not generate relationships from title-string similarity.

11. ANIME EFFECT
==================================================
Prepare an AnimeFinder metric called “Anime Effect”.
Future goal: evaluate whether anime adaptation timing correlates with increased source-material sales/popularity.
Only calculate if reliable before/after historical data exists.
Otherwise display exactly/conceptually:
“Historical sales data required.”

Never confuse MAL Rank, Popularity Rank and Score.

==================================================
16. SERVICE ARCHITECTURE
==================================================
Keep orchestration outside React components where practical.
Preferred conceptual flow:
AnimeProvider
→ AnimeDetailsService
→ FranchiseService
→ AnalyticsService
→ NerdDataService
→ RegionalDataService

Reuse existing provider caches by MAL ID.
Do not re-request director, staff, relations, scores or studio when already cached.

==================================================
17. PROGRESSIVE LOADING + TIMEOUTS
==================================================
Anime Details stays lightweight.
Deep Analysis loads progressively:
Priority 1: existing AnimeFinder data
Priority 2: franchise calculations
Priority 3: production metadata
Priority 4: market data
Priority 5: regional/global data

Each section renders independently.
Use Promise.allSettled() or equivalent where useful.
One provider failure must not break the page.
No endless loaders.
Every provider path must resolve to success, partial, empty, error or timeout.
