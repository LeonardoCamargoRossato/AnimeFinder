ANIMEFINDER — HAMLET AI V1.2
PERSISTENT CONVERSATIONS + COMPACT RECOMMENDATIONS + WATCHED FLOW + PDF EXPORT

Repository:
LeonardoCamargoRossato/AnimeFinder

IMPORTANT:
This is an incremental upgrade of the current working AnimeFinder + Hamlet AI.

DO NOT rebuild Hamlet.
DO NOT replace the current Gemini reliability/fallback architecture.
DO NOT break the existing Supabase authentication, catalog, Personal Knowledge,
Master Data, Jikan integration or GitHub Pages deployment.

The current Hamlet AI conversation and recommendation flow is already working.

The goal of V1.2 is to improve UX and introduce automatically persistent
conversation history that can later become another Personal Knowledge source
for Hamlet.

==================================================
1. COMPACT RECOMMENDATION CARDS
==================================================

The recommendation cards shown beside the Hamlet conversation are currently too large.

Redesign them to be significantly more compact and easier to scan.

The user should be able to see several recommendations at the same time without
excessive scrolling.

Keep the existing AnimeFinder visual identity.

Each compact recommendation card should prioritize:

- poster
- title
- score
- year
- episodes / format when available
- essential metadata
- quick actions

Do not create giant poster cards.

Prefer a compact grid/list optimized for browsing.

Desktop should display multiple recommendation cards simultaneously.

Responsive behavior must remain good on mobile.

==================================================
2. WATCHED / CLASSIFICATION ACTION FROM HAMLET
==================================================

Every recommendation should provide a quick action similar to:

Mark as Watched

When clicked, do NOT immediately finalize the operation.

Open a small dialog/popover asking:

"How should this anime be added?"

Options:

1. Already classified
2. Needs classification
3. Cancel

If the user chooses:

Already classified

follow the existing AnimeFinder classification/watch flow.

If the user chooses:

Needs classification

mark/import the anime appropriately and place it in the existing:

Needs Classification

workflow/list/category.

This is especially important when Hamlet recommends an anime the user has
already watched but which is not correctly represented in the personal catalog.

The update must persist in Supabase.

Supabase remains the source of truth.

Do NOT use localStorage as persistent storage.

After marking an anime as watched, update the Hamlet recommendation UI immediately.

==================================================
3. NEVER LOSE THE ACTIVE CONVERSATION
==================================================

Currently, if the user opens an anime recommendation and later returns to
Hamlet AI, the conversation can disappear.

Fix this.

Navigating inside AnimeFinder must NOT destroy the active Hamlet conversation.

The conversation must survive navigation between:

- Hamlet
- Anime Details
- Personal Catalog
- other AnimeFinder screens
- browser refresh

When returning to Hamlet, restore the conversation exactly where the user stopped.

==================================================
4. AUTOMATIC CONVERSATION PERSISTENCE
==================================================

IMPORTANT CHANGE:

There must NOT be a manual "Save Conversation" requirement.

Every Hamlet conversation must be automatically persisted in Supabase.

As soon as a real conversation begins, create/reuse an active conversation
record.

Messages should then be persisted automatically as the conversation evolves.

The user should never have to remember to save a conversation.

Avoid creating duplicate conversations on every message.

Maintain one active conversation ID throughout the session/search.

Supabase is the source of truth.

==================================================
5. AUTOMATIC AI TITLE AND DESCRIPTION
==================================================

Hamlet should automatically generate metadata for each conversation.

Generate:

- short conversation title
- short description

Example:

Title:
RPG and Game-World Anime

Description:
Search for RPG-style anime with levels, classes, skills and virtual worlds.

Another example:

Title:
Dark Fantasy Recommendations

Description:
Search for darker fantasy anime with mature themes and strong world-building.

Keep both concise.

Do NOT generate huge summaries.

The automatic title/description should be generated after there is enough
conversation context to understand the search.

Do not call the AI after every single message just to regenerate metadata.

Generate/update intelligently when useful.

Store these values in Supabase.

==================================================
8. EDIT CONVERSATION METADATA
==================================================

Each item in Conversation History must have a small Edit action/icon.

Example:

✎ Edit

Clicking Edit opens a compact dialog allowing the user to manually edit:

- Conversation title
- Conversation description

Pre-fill the fields with the AI-generated title and description.

The user can then improve/rename them.

Example:

AI generated:

Title:
RPG and Game-World Anime

User changes it to:

Best RPG / Isekai Anime Search

Allow Save and Cancel.

Persist the edited metadata in Supabase.

Once manually edited, do NOT automatically overwrite the user's custom title
or description with another AI-generated version.

Track whether metadata is:

AI generated

or:

User edited

through an appropriate field such as title_source / metadata_source.

==================================================
9. CONTINUE CONVERSATION
==================================================

A conversation from Conversation History can be opened again.

When opened:

- restore all messages
- restore interpreted Hamlet criteria
- restore recommendations when appropriate
- restore conversation ID
- continue from exactly where the conversation stopped
- update last_accessed_at
- increment access_count

The user should be able to continue an old search naturally.

==================================================
10. CONTINUE LAST CONVERSATION
==================================================

Near the Hamlet AI controls, add:

Continue Last Conversation

This provides a shortcut to the most recently active conversation.

Clicking it should restore the latest conversation directly without requiring
the user to open Conversation History first.

If the current conversation is already the latest active conversation, avoid
creating duplicate state.

==================================================
11. START NEW CONVERSATION
==================================================

Provide a clear:

New Conversation

action.

Starting a new conversation must NOT delete the previous conversation.

The previous conversation is already safely stored in Supabase.

New Conversation:

- clears the visible Hamlet conversation
- creates a new conversation context
- resets interpreted criteria
- resets current recommendations
- preserves all previous history

The existing "Clear Conversation" control should be reviewed.

Prefer renaming/replacing it with:

New Conversation

because conversations are now automatically persisted.

Do not make "Clear" imply that historical data is being deleted.
